# EXPO נדל"ן – אפליקציית אנדרואיד

האפליקציה מציגה את האתר **https://nadlanh.co.il** בתוך אפליקציית אנדרואיד שאפשר להעלות ל־Google Play.
היא **מסונכרנת עם האתר תמיד**: כל שינוי שתעשו באתר יופיע באפליקציה מיד, בלי לעדכן את האפליקציה.

## מה יש באפליקציה
- טעינה ישירה של האתר, מסך פתיחה ושם האפליקציה "EXPO נדל"ן"
- כפתור "חזור" של אנדרואיד חוזר לעמוד הקודם באתר
- קישורים לאתרים אחרים, WhatsApp, טלפון ומייל נפתחים באפליקציה המתאימה
- מסך "אין חיבור לאינטרנט" עם כפתור "נסו שוב"

## שלב 1 – אייקון ומסך פתיחה ✅
האייקון ומסך הפתיחה כבר נוצרו מהלוגו (בתיקייה `assets/`).
בתיקייה `store/` יש תמונות מוכנות ל־Google Play: אייקון 512×512 ותמונת נושא 1024×500.
אם הלוגו ישתנה, החליפו את הקבצים ב־`assets/` והריצו: `npm install && npm run icons && npx cap sync android`

## שלב 2 – בניית האפליקציה (בלי להתקין כלום)
הבנייה נעשית אוטומטית ב־GitHub Actions:
1. ב־GitHub, היכנסו ל־**Actions** ובחרו **"בניית אפליקציית אנדרואיד"**
2. בסיום הריצה הורידו את **nadlanh-android** מתחתית הדף
3. בפנים יש קובץ **APK** שאפשר להתקין ישר על הטלפון לבדיקה

## שלב 3 – מפתח חתימה (פעם אחת בלבד!)
Google Play מחייב שהאפליקציה תהיה חתומה. במחשב עם Java מריצים:
```
keytool -genkey -v -keystore release.keystore -alias nadlanh -keyalg RSA -keysize 2048 -validity 10000
```
⚠️ **שמרו את הקובץ ואת הסיסמה במקום בטוח.** בלעדיהם לא תוכלו לעדכן את האפליקציה לעולם.

ב־GitHub, תחת **Settings ← Secrets and variables ← Actions**, הוסיפו:
| שם | ערך |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | תוכן הקובץ בקידוד base64 (`base64 -w0 release.keystore`) |
| `ANDROID_KEYSTORE_PASSWORD` | סיסמת ה־keystore |
| `ANDROID_KEY_ALIAS` | `nadlanh` |
| `ANDROID_KEY_PASSWORD` | סיסמת המפתח |

מעכשיו כל בנייה תייצר גם קובץ **AAB** חתום, וזה הקובץ שמעלים ל־Google Play.

## שלב 4 – העלאה ל־Google Play
1. פתחו חשבון ב־[Google Play Console](https://play.google.com/console) (תשלום חד־פעמי של 25$)
2. **Create app**: שם "EXPO נדל"ן", שפה עברית, סוג App, חינמית
3. מלאו את פרטי החנות: תיאור, אייקון 512×512, תמונת נושא 1024×500, ולפחות 2 צילומי מסך
4. מלאו את השאלונים: מדיניות פרטיות (קישור לעמוד באתר), דירוג תוכן וקהל יעד
5. **Testing ← Internal testing**: העלו את קובץ ה־AAB ובדקו
6. כשהכול תקין: **Production ← Create release** והעלו את אותו קובץ

> חשבונות מפתח אישיים חדשים צריכים לפעמים להריץ בדיקה סגורה עם 12 בודקים במשך 14 יום לפני הפרסום. חשבון של **ארגון/עסק** פטור מזה.

## עדכונים
- **תוכן**: מעדכנים באתר כרגיל, ואין צורך לעשות שום דבר באפליקציה
- **גרסה חדשה של האפליקציה** (אייקון, שם וכו'): מריצים שוב את הבנייה ומעלים את קובץ ה־AAB החדש. מספר הגרסה עולה אוטומטית.

## הגדרות חשובות
